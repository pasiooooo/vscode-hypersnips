# 性能重构试用报告

本分支为 `codex/performance-refactor`，基于 `d851872`。插件保持版本 `0.1.4` 和标识 `pasiooooo.vscode-hypersnips`。原工作目录的插件市场准备文件未带入此分支。

**旧试用包 `4536c43` 已发现连续编辑时的字符串保留问题，请安装替换包。** 本轮修复了三处已复现的内存保留，并让多位置修改之间的未变文本块继续复用。合并 main 仍需用户安装试用确认；本轮不创建标签、不发布 GitHub Release 或插件市场版本。

## 最终基准

以下完整基准对应生产源码 `beb2205`，后续宿主测试及报告提交不改变生产代码。环境为 Windows、Intel Core i7-14700KF、Node v25.8.1；每组预热 10 次、测量 200 次，在同一进程比较冻结算法和当前实现。完整数据见 [performance-results-beb2205.json](performance-results-beb2205.json)。

| 虚构输入上的操作 | 原实现中位数 / P95，ms | 当前中位数 / P95，ms | 中位数减少 |
| --- | ---: | ---: | ---: |
| 1 MiB 局部编辑、上下文及名称同步预判 | 61.4043 / 72.1271 | 0.9021 / 1.0789 | 98.5% |
| 100 行 × 128 列对齐 | 120.5781 / 133.5729 | 7.1945 / 11.2260 | 94.0% |
| 20 行 × 32 列，含二元运算符 | 12.2862 / 15.5936 | 1.1382 / 1.9025 | 90.7% |
| 编译 10,000 条片段 | 638.4369 / 1131.7022 | 6.2097 / 8.6404 | 99.0% |

上表基线为 `d851872`。三个约定门槛均通过：局部编辑中位数至少降低 70%、P95 不超过 10 ms、宽表对齐中位数至少降低 50%。1 MiB 普通修改重新解析 1 块、复用 14,575 块。

多位置编辑另外与前一试用版本 `4536c43` 的状态算法比较；该测试专用副本共享现有解析 helper，因此只比较文档状态算法：

| 1 MiB 同一事件中的修改数量 | 4536c43 中位数 / P95，ms | 当前中位数 / P95，ms | 当前重新解析 / 复用块数 |
| --- | ---: | ---: | ---: |
| 首尾两处 | 26.3904 / 42.6674 | 0.9444 / 1.2006 | 2 / 14,574 |
| 分散 100 处 | 48.6747 / 63.5627 | 1.1280 / 1.5386 | 100 / 14,476 |

首次构建 1 MiB 状态为 **28.9076 / 34.1426 ms**；文首插入改变后续结构的 Markdown 围栏为 **18.6804 / 20.8563 ms**。它们允许全量或大范围重新解析，没有固定时间承诺。内存安全需要拥有字符串存储：独立的同算法对照中，所有权复制使冷构建增加约 6.83 ms、普通/批量修改增加约 0.18–0.23 ms；不能为回收这些毫秒而重新引入旧文本保留。

这些数值是函数计算耗时，不含编辑器通信、渲染、原有 150 ms 防抖、字体进程启动和其他扩展。编译基线受 V8/负载影响较大，不保证日常使用具有同样绝对倍率。共享 CI 检查行为和扫描/进程次数，不以绝对毫秒作门槛。

## 内存回归及修复

之前的创建/编辑/整体释放测试没有覆盖同一文档连续编辑，因而漏掉了字符串切片保留旧缓冲区的问题。新增三项先失败、修复后通过的回归：

| 场景 | 修复前 GC 后保留/增长 | 修复后 |
| --- | ---: | ---: |
| 同一 1 MiB 文档，100 次分散行编辑，仅保留当前/前版 | 104,978,424 bytes | 100,360 bytes |
| 16 MiB 文档删除至当前/前版仅 125/126 字符 | 16,743,784 bytes | -33,976 bytes |
| 1 MiB 未完成跨行块内缓存 32 个上下文 | 33,598,408 bytes | 44,072 bytes |

原始记录和阈值见 [performance-memory-results-beb2205.json](performance-memory-results-beb2205.json)。负值是 GC/测量波动，不代表负分配。三处所有者分别是持久块的 raw/sanitized、缩短后的 snapshot.text，以及缓存环境名引用的临时解析前缀。修复为持久字符串分离存储，保留原 UTF-16 码元、长度和偏移，没有编码转换。

`npm run check` 使用 `--expose-gc` 执行这些回归。阈值为宽松的 8/12 MiB，用于拦截已复现的 16–100 MiB 保留，而非易波动的时间门槛。独立 Unicode 混合输入和旧快照释放探针也复现了问题及修复。

另一个合成场景经过 20 次预热、100 次构建/编辑/释放后，堆从 88,988,328 变为 88,868,720 字节，趋势平稳。这些测试覆盖已确认的所有者，不构成全部路径无泄漏的证明；异步任务可在完成前合法持有快照。

## 实现范围

- 共享不可变文档状态保留当前/前版，使用相对 token 和行/块检查点。上下文、片段过滤、Enter/Tab、名称同步、转换及对齐共用快照；前缀查询与全文清理语义分别保留。
- 多次修改按同一个旧版本坐标处理。合并保守的受影响块区间，映射中间未变间隔，只在新旧块边界精确重合时复用。状态不同则传播旧 token；状态收敛时共享到当前间隔末尾，不跨越下个修改区。结构性解析可越过多个间隔。修改片段统一拼接一次，同位置插入顺序和重叠错误保持一致。
- 正文编辑先判断是否触及环境名称；上下文键只在值变化时发送。配置、版本断档或无效更新走重建；关闭文档释放状态。异步任务检查版本，禁止旧结果覆盖新文档。
- 对齐按单元格组织锚点，复用内容宽度，顺序累计浮点值；按连续空白段产生相同的原文编辑；运算符判断检查去尾空白后的末尾。各位置先判断资格，再按环境合并。
- 字体只收集受影响环境中的文档字符；保留四组完整字体配置，合并未启动缺字请求，跳过过期队列。缓存覆盖检查省去重复枚举，新增测量后失效；覆盖正则编译失败沿用原收集路径，缺字仍做原生校准。
- 片段解析使用游标；加载先构建整张新表，失败保留旧表。同次操作的重复回调合并，后续独立加载仍执行 global。管理器输入只更新内容、脏状态及按钮，新分析通过后刷新结果，保留冲突检查。
- 自动匹配跳过不用的部分前缀，手动匹配限制最大前缀长度。无需遮罩的文本避免字符数组；无三连标记时跳过围栏逐行扫描。完整块复用已计算的清理结果，未完成尾部保留全文回退。

历史单项探索结果见 [performance-extra-measurements.json](performance-extra-measurements.json)。其中字体进程为模拟器，1.4834→0.0391 ms 只代表宽表的 JavaScript 缓存请求，不代表原生启动或完整输入延迟。旧 JSON 仅作历史记录，不代替本报告数据。

## 验证证据

- `npm run check` 通过类型检查、原有测试及增量、三类内存、对齐、字体调度、片段加载/管理器、补全与清理回归，含真实 Windows 字体校准。
- 逐编辑对照覆盖精确上下文、环境范围、编辑及光标，中英文/组合字符/Tab/CRLF、转义、注释、围栏、verbatim、跨行未完成命令、嵌套/自定义环境、同位置插入、批量坐标、版本/配置重建及旧快照不变性。
- 新批量算法的独立审查比较 2,055 个快照、1,510 个批次、129,708 个逐位置状态；6,163 个 Enter/对齐位置及 389,122 个光标映射一致。16 万行更新仅解析 1 块、复用 159,999 块，避免 spread 参数数量上限。独立内存语义审查另比较 1,500 状态、177,583 逐位置结果。
- 对齐精确编辑/光标对照覆盖分数、极大/极小/非有限宽度、Tab、运算符组与幂等；字体测试检查进程合并、四组缓存淘汰、过期任务零启动、Map 隔离、覆盖失效、Unicode/孤立代理项及失败回退。
- 加载和管理器 VM 测试执行实际代码，覆盖解析/global/读取失败、后续恢复、profile 回调时序、过期分析、hash/mtime/未保存编辑冲突。正则、优先级、动态占位符及 global 语义保留。
- 隔离真实 VS Code 宿主 **十组**测试通过，包括动态占位符、自动/手动片段、名称同步、Tab/Enter、注释、对齐开关、过期任务、实际撤销/重做及 20 次打开/编辑/关闭。新增测试确认相隔 200 行的双修改在同一事件到达，撤销重做及后续数学片段仍正确。

本报告封存时，替换包最终提交的远程 Windows/Linux CI 与 VSIX 校验待验证；交付记录提供对应提交的链接和校验结果，不用旧运行代替。旧 `4536c43` 曾通过 CI，但新增连续编辑场景揭示其覆盖不足，因此仍需替换。

## 剩余成本与试用条件

文档更新仍复制文本并重建块偏移索引；很长的未完成跨行结构仍共享一个块。首次配对/清理查询可能访问全部块；深层嵌套仅做正确性抽查，不承诺性能上限。没有证据支持现在增加持久索引或跨版本配对缓存。

原生字体测量仍是一次性异步 Windows 进程，运行中的进程正常完成，过期结果禁止写回。其他系统保持 Unicode 列宽回退；固定 ASCII 预热保留，以减少后续新进程。本轮不增加常驻进程、Worker、JavaScript 沙箱或更换正则引擎。任意用户正则/代码仍可能耗时无上限，加载失败也无法撤销用户 global 已产生的外部副作用。

按 [安装与试用清单](performance-testing.md) 安装最新哈希的替换 VSIX 并重新加载；仍显示 0.1.4，以文件名区分。恢复时安装原稳定 0.1.4 包，不要恢复到已发现内存问题的 4536c43，也不删除用户片段或设置。

收到用户试用确认后才将最新 main 合入性能分支并复测；行为有变化则重新提供包。通过后保留分阶段提交合并。当前只推送性能分支，不合并 main、创建发布标签或发布版本。
